# Step 1a.6 evidence: element graph spike (D3)

- Date: 2026-11-20
- Step: 1a.6 of the Phase 1 execution plan
- Purpose: the evidence for decision D3 (arena and ID design, ADR 0017), under the decision methodology (execution plan §2.5)

## Questions

1. **Storage.** Which properties of the 82 KerML metaclasses must the graph store, and which can it derive? How should they be stored?
2. **Identity.** Should elements be addressed internally by dense arena indices mapped to their UUIDs (the default), or directly by UUID?
3. **Performance.** How do the two designs compare at 1M elements: build time, memory, walking the ownership tree, typed access to a relationship end, and lookup by UUID? The relevant §7 budgets are: re-resolve < 1 s, find references over 1M elements < 2 s, a 1M-element cold load < 30 s, and browser memory < 1 GB.
4. **Implied relationships.** What does the abstract syntax say about them, and where should they be stored?
5. **Constraints.** Does the default build for wasm32 and on Rust 1.89, and does it need new dependencies?

## Method

- **The metamodel.** A survey of `KerML/normative/KerML.xmi` (Python, standard library): every `ownedAttribute` of the 82 metaclasses, whether it is derived, and what it redefines.
- **A throwaway crate, `spike1a6`**, outside the workspace, depending only on `uuid` 1. It builds the same model twice: one root package, 1,000 classifiers, and 333,333 features, each with its owning membership and a feature typing to one of the classifiers. That is 1,002,000 elements.
  - **Option A**, the default, uses dense `u32` indices with a UUID side table, and stores the canonical core: ownership links, `source` and `target`, names, and flag bits. `FeatureTyping::type` is a view over `target`.
  - **Option B** is a property bag keyed by UUID, as in the KerML 10.4 JSON: each element is a map from property name to value, with references as UUIDs.
- **Measurement.** A counting global allocator measures the memory. Each operation is timed in a release build, taking the best of 5 runs, on the development machine (WSL2).
- **Fragments.** A last measurement assembles the graph from 100 per-file fragments with file-local indices.

## Results

### The stored properties

Of the 210 attributes of the 82 KerML metaclasses, **134 are derived and 76 are stored**. Of the 76, every relationship end redefines `Relationship::source` or `Relationship::target`, directly or through another end. For example, `FeatureTyping::type` redefines `Specialization::general`, which redefines `target`, and `Redefinition::redefinedFeature` redefines `Subsetting::subsettedFeature`, which redefines `general`. The ends are 30 attributes of 20 metaclasses. The rest are:
- **ownership:** `Element::owningRelationship`, `ownedRelationship`, and `Relationship::owningRelatedElement`, `ownedRelatedElement`
- **identity and names:** `elementId`, `aliasIds`, `declaredName` and `declaredShortName`, `memberName` and `memberShortName`
- **flags:** booleans such as `isAbstract`, the eight of `Feature`, `isImplied` and `isImpliedIncluded`
- **enumerations:** `direction` and `visibility`
- **literal values and texts:** `value`, `operator`, `body`, `locale` and `language`

So a store of the canonical core holds everything a model states. The typed properties are views generated from the redefinitions, and the derived ones are computed (step 1a.8).

### Performance at 1,002,000 elements

| | A: arena and canonical core | B: property bag by UUID |
|---|---|---|
| Build | 209 ms | 414 ms |
| Memory | **186 MiB** (195 B per element) | 558 MiB (584 B per element) |
| Walk the ownership tree | **5.7 ms** | 376 ms |
| Typed access: every typing's type name | **3.4 ms** | 126 ms |
| 1M lookups by UUID (SipHash) | 84 ms | 23 ms |

- **Walking and typed access**, which resolution, implied relationships and queries do all the time, are **35–65 times faster** in A. In A they are index arithmetic; in B each step is a hash lookup and a string-keyed map.
- **Lookup by UUID** is the same operation in both: one hash lookup. The difference is the access pattern. A looks the ids up in creation order, which jumps around its table, while B iterates its own table in order. Both take under 0.1 s for a million lookups, and in A they happen only at the API boundary.
- **Memory:** A is 3 times smaller, and its `ElemA` (104 bytes) could shrink further by moving `source` and `target` out of the element struct.
- **Hashing:** with FxHash instead of SipHash, A's lookups take 29 ms. But the server receives client-assigned UUIDs (PROJECT_PLAN §4.3), so the keyed SipHash of the standard library is kept against hash flooding, and no dependency is added.
- **Fragments:** assembling 1M elements from 100 per-file fragments takes **143 ms**, most of it filling the UUID index.

### Implied relationships

KerML 8.3.2 defines `Relationship::isImplied`: "Whether this Relationship was generated by tooling to meet semantic rules, rather than being directly created by a modeler". It also defines `Element::isImpliedIncluded`: either all the implied relationships of an element are among its `ownedRelationship`s, or none are. KerML 10.3 (Note 5 on `includesImplied`) then requires an interchange file to include all of them or none. Implied relationships are therefore owned relationships with a flag, which tooling must be able to add or leave out as a whole.

### Constraints

The spike builds for wasm32-unknown-unknown and on Rust 1.89, with `uuid` as its only dependency. `uuid` is already in the workspace and was checked in the 1a.0 spike.

`src/main.rs`:

```rust
//! D3 spike (step 1a.6): two element-graph designs on the same 1M-element model.
//!
//! A (default): an arena of dense `u32` indices, a UUID side table, and the canonical stored
//!   core of the KerML abstract syntax: ownership links, relationship `source`/`target`, names
//!   and scalar flags. Typed properties such as `FeatureTyping::type` are views over `target`.
//! B: a property bag keyed by UUID, as in the KerML 10.4 JSON: each element a map from property
//!   name to value, references as UUIDs.
use std::alloc::{GlobalAlloc, Layout, System};
use std::collections::HashMap;
use std::sync::atomic::{AtomicUsize, Ordering::Relaxed};
use std::time::Instant;
use uuid::Uuid;

struct Counting;
static LIVE: AtomicUsize = AtomicUsize::new(0);
unsafe impl GlobalAlloc for Counting {
    unsafe fn alloc(&self, l: Layout) -> *mut u8 { LIVE.fetch_add(l.size(), Relaxed); System.alloc(l) }
    unsafe fn dealloc(&self, p: *mut u8, l: Layout) { LIVE.fetch_sub(l.size(), Relaxed); System.dealloc(p, l) }
    unsafe fn realloc(&self, p: *mut u8, l: Layout, n: usize) -> *mut u8 {
        LIVE.fetch_add(n, Relaxed); LIVE.fetch_sub(l.size(), Relaxed); System.realloc(p, l, n)
    }
}
#[global_allocator]
static A: Counting = Counting;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
enum Mc { Package, OwningMembership, Feature, FeatureTyping, Classifier }

// ---------- Option A ----------
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
struct Ix(u32);

struct ElemA {
    mc: Mc,
    flags: u32,                    // the boolean attributes, one bit each
    name: Option<Box<str>>,        // declaredName (memberName, … in their own slots)
    owning: Option<Ix>,            // owningRelationship / owningRelatedElement
    owned: Vec<Ix>,                // ownedRelationship / ownedRelatedElement, in order
    source: Vec<Ix>,               // relationships only
    target: Vec<Ix>,
}
struct GraphA { el: Vec<ElemA>, ids: Vec<Uuid>, by_id: HashMap<Uuid, Ix> }
impl GraphA {
    fn add(&mut self, id: Uuid, mc: Mc, name: Option<&str>) -> Ix {
        let ix = Ix(self.el.len() as u32);
        self.el.push(ElemA { mc, flags: 0, name: name.map(Into::into), owning: None, owned: Vec::new(), source: Vec::new(), target: Vec::new() });
        self.ids.push(id); self.by_id.insert(id, ix); ix
    }
    fn own(&mut self, parent: Ix, child: Ix) { self.el[parent.0 as usize].owned.push(child); self.el[child.0 as usize].owning = Some(parent); }
    fn e(&self, ix: Ix) -> &ElemA { &self.el[ix.0 as usize] }
    /// `FeatureTyping::type` (KerML 8.3.3.3.4): redefines `general`, which redefines `target`.
    fn typing_type(&self, ft: Ix) -> Ix { self.e(ft).target[0] }
}

// ---------- Option B ----------
#[allow(dead_code)]
enum Val { Ref(Uuid), Refs(Vec<Uuid>), Str(String), Bool(bool) }
struct ElemB { mc: Mc, props: HashMap<&'static str, Val> }

struct Rng(u64);
impl Rng { fn next(&mut self) -> u64 { self.0 ^= self.0 << 13; self.0 ^= self.0 >> 7; self.0 ^= self.0 << 17; self.0 } }
fn uuid(r: &mut Rng) -> Uuid { uuid::Builder::from_random_bytes(((r.next() as u128) << 64 | r.next() as u128).to_le_bytes()).into_uuid() }

const FEATURES: usize = 333_333; // × 3 elements (membership, feature, typing) ≈ 1M
const TYPES: usize = 1_000;

fn mib(b: usize) -> f64 { b as f64 / (1 << 20) as f64 }

fn main() {
    let runs = 5;
    let mut best = HashMap::<&str, f64>::new();
    let mut note = |k: &'static str, v: f64| { let e = best.entry(k).or_insert(f64::MAX); if v < *e { *e = v } };
    let (mut mem_a, mut mem_b, mut n_a) = (0, 0, 0);
    for _ in 0..runs {
        // ---- A ----
        let before = LIVE.load(Relaxed);
        let t = Instant::now();
        let mut r = Rng(7);
        let mut g = GraphA { el: Vec::new(), ids: Vec::new(), by_id: Default::default() };
        let root = g.add(uuid(&mut r), Mc::Package, Some("Root"));
        let types: Vec<Ix> = (0..TYPES).map(|i| { let m = g.add(uuid(&mut r), Mc::OwningMembership, None); g.own(root, m); let c = g.add(uuid(&mut r), Mc::Classifier, Some(&format!("T{i}"))); g.own(m, c); c }).collect();
        for i in 0..FEATURES {
            let m = g.add(uuid(&mut r), Mc::OwningMembership, None); g.own(root, m);
            let f = g.add(uuid(&mut r), Mc::Feature, Some(&format!("f{i}"))); g.own(m, f);
            let ft = g.add(uuid(&mut r), Mc::FeatureTyping, None); g.own(f, ft);
            g.el[ft.0 as usize].source.push(f);
            g.el[ft.0 as usize].target.push(types[i % TYPES]);
        }
        note("A build", t.elapsed().as_secs_f64() * 1e3);
        mem_a = LIVE.load(Relaxed) - before; n_a = g.el.len();
        // walk by ownership
        let t = Instant::now();
        let mut stack = vec![root]; let mut seen = 0usize;
        while let Some(x) = stack.pop() { seen += 1; stack.extend(g.e(x).owned.iter().copied()); }
        assert_eq!(seen, g.el.len());
        note("A walk ownership", t.elapsed().as_secs_f64() * 1e3);
        // typed access: every typing's type name
        let t = Instant::now();
        let mut len = 0usize;
        for (i, e) in g.el.iter().enumerate() { if e.mc == Mc::FeatureTyping { len += g.e(g.typing_type(Ix(i as u32))).name.as_deref().map_or(0, str::len); } }
        std::hint::black_box(len);
        note("A typed access", t.elapsed().as_secs_f64() * 1e3);
        // UUID lookups
        let t = Instant::now();
        let mut hit = 0usize;
        for id in g.ids.iter().step_by(1) { hit += g.by_id[id].0 as usize & 1; }
        std::hint::black_box(hit);
        note("A uuid lookup (all)", t.elapsed().as_secs_f64() * 1e3);
        drop(g);

        // ---- B ----
        let before = LIVE.load(Relaxed);
        let t = Instant::now();
        let mut r = Rng(7);
        let mut g: HashMap<Uuid, ElemB> = HashMap::new();
        let add = |g: &mut HashMap<Uuid, ElemB>, id: Uuid, mc: Mc, name: Option<&str>| {
            let mut props = HashMap::new();
            props.insert("elementId", Val::Str(id.to_string()));
            if let Some(n) = name { props.insert("declaredName", Val::Str(n.to_owned())); }
            g.insert(id, ElemB { mc, props });
        };
        let own = |g: &mut HashMap<Uuid, ElemB>, parent: Uuid, child: Uuid| {
            if let Val::Refs(v) = g.get_mut(&parent).unwrap().props.entry("ownedRelationship").or_insert(Val::Refs(Vec::new())) { v.push(child) }
            g.get_mut(&child).unwrap().props.insert("owningRelationship", Val::Ref(parent));
        };
        let root = uuid(&mut r); add(&mut g, root, Mc::Package, Some("Root"));
        let types: Vec<Uuid> = (0..TYPES).map(|i| { let m = uuid(&mut r); add(&mut g, m, Mc::OwningMembership, None); own(&mut g, root, m); let c = uuid(&mut r); add(&mut g, c, Mc::Classifier, Some(&format!("T{i}"))); own(&mut g, m, c); c }).collect();
        for i in 0..FEATURES {
            let m = uuid(&mut r); add(&mut g, m, Mc::OwningMembership, None); own(&mut g, root, m);
            let f = uuid(&mut r); add(&mut g, f, Mc::Feature, Some(&format!("f{i}"))); own(&mut g, m, f);
            let ft = uuid(&mut r); add(&mut g, ft, Mc::FeatureTyping, None); own(&mut g, f, ft);
            let p = &mut g.get_mut(&ft).unwrap().props;
            p.insert("typedFeature", Val::Ref(f)); p.insert("type", Val::Ref(types[i % TYPES]));
        }
        note("B build", t.elapsed().as_secs_f64() * 1e3);
        mem_b = LIVE.load(Relaxed) - before;
        let t = Instant::now();
        let mut stack = vec![root]; let mut seen = 0usize;
        while let Some(x) = stack.pop() { seen += 1; if let Some(Val::Refs(v)) = g[&x].props.get("ownedRelationship") { stack.extend(v.iter().copied()); } }
        assert_eq!(seen, g.len());
        note("B walk ownership", t.elapsed().as_secs_f64() * 1e3);
        let t = Instant::now();
        let mut len = 0usize;
        for e in g.values() { if e.mc == Mc::FeatureTyping { if let Some(Val::Ref(ty)) = e.props.get("type") { if let Some(Val::Str(n)) = g[ty].props.get("declaredName") { len += n.len(); } } } }
        std::hint::black_box(len);
        note("B typed access", t.elapsed().as_secs_f64() * 1e3);
        let ids: Vec<Uuid> = g.keys().copied().collect();
        let t = Instant::now();
        let mut hit = 0usize;
        for id in &ids { hit += g[id].props.len() & 1; }
        std::hint::black_box(hit);
        note("B uuid lookup (all)", t.elapsed().as_secs_f64() * 1e3);
        let _ = Val::Bool(false);
    }
    // Assembly from per-file fragments: 100 fragments of ~10k elements with file-local indices,
    // appended into one graph with their indices shifted.
    let mut frag_best = f64::MAX;
    for _ in 0..runs {
        let mut r = Rng(11);
        let frags: Vec<GraphA> = (0..100).map(|_| {
            let mut g = GraphA { el: Vec::new(), ids: Vec::new(), by_id: HashMap::new() };
            let root = g.add(uuid(&mut r), Mc::Package, Some("P"));
            for i in 0..3_333 {
                let m = g.add(uuid(&mut r), Mc::OwningMembership, None); g.own(root, m);
                let f = g.add(uuid(&mut r), Mc::Feature, Some(&format!("f{i}"))); g.own(m, f);
                let ft = g.add(uuid(&mut r), Mc::FeatureTyping, None); g.own(f, ft);
                g.el[ft.0 as usize].source.push(f);
            }
            g
        }).collect();
        let t = Instant::now();
        let mut all = GraphA { el: Vec::new(), ids: Vec::new(), by_id: HashMap::new() };
        for frag in frags {
            let off = all.el.len() as u32;
            let shift = |ix: Ix| Ix(ix.0 + off);
            for (e, id) in frag.el.into_iter().zip(frag.ids) {
                all.by_id.insert(id, Ix(all.el.len() as u32));
                all.ids.push(id);
                all.el.push(ElemA { owning: e.owning.map(shift), owned: e.owned.into_iter().map(shift).collect(), source: e.source.into_iter().map(shift).collect(), target: e.target.into_iter().map(shift).collect(), ..e });
            }
        }
        frag_best = frag_best.min(t.elapsed().as_secs_f64() * 1e3);
        std::hint::black_box(all.el.len());
    }
    println!("assemble 100 fragments (1M elements): {frag_best:.1} ms (best of {runs})");
    println!("elements: {n_a}");
    let mut keys: Vec<_> = best.iter().collect(); keys.sort_by_key(|(k, _)| *k);
    for (k, v) in keys { println!("{k:24} {v:8.1} ms (best of {runs})"); }
    println!("A memory {:.0} MiB ({:.0} B/element); B memory {:.0} MiB ({:.0} B/element)", mib(mem_a), mem_a as f64 / n_a as f64, mib(mem_b), mem_b as f64 / n_a as f64);
    println!("size_of ElemA {} B, ElemB {} B", std::mem::size_of::<ElemA>(), std::mem::size_of::<ElemB>());
}
```
